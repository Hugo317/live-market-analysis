In 2026-09, dropped the live/current-quote view (`get_quotes()`) entirely due to tight free-tier
quotas (EODHD 20 calls/day unbatched, Twelve Data 800/day+8/min, iTick 5/min). Dashboard is now
historical-only, fetched daily in bulk (US+Asia) or on demand (Europe, one symbol at a time).

**How the work was split** (sequenced, not fully parallel, because of a shared contract):
1. `api-info-manager` went first alone — it owns `fetch_raw.py` and had to decide the new
   `data/raw/*.json` shape. Gave it the full contract spec explicitly rather than letting it
   invent one, so downstream agents could be briefed with certainty.
2. `data-handler` and `dashboard-builder` ran in parallel once the contract was fixed — both only
   needed to know the fetch_raw.py public API and JSON shape, not each other's work, EXCEPT for
   one cross-dependency: dashboard-builder needed a "latest bar per symbol" helper that
   data-handler might or might not add to analyze.py. Handled by telling dashboard-builder to
   write a `getattr(analyze, "latest_per_symbol", None)`-guarded shim with an inline fallback —
   this let both agents proceed without blocking on each other, and self-resolved correctly once
   data-handler's version landed under the same name/signature I'd suggested to both.
3. `tester` ran last against the finished pipeline.

**Final contract** (see project CLAUDE.md for the authoritative up-to-date version — this note is
a snapshot, verify against CLAUDE.md/code before relying on specifics like function names):
- `fetch_raw.py`: `fetch_bulk_historical(twelve_data_symbols, itick_pairs, period="d")` (US+Asia
  only, merge-writes, never touches EODHD) and `fetch_symbol_historical(provider, *args,
  period="d")` (any one provider, on demand, merge-writes — the only path allowed to call EODHD).
- Raw JSON shape changed from flat list-of-quotes to `{"<symbol>": [bar, ...]}`
  (`{"<region>:<code>": {"data": [bar,...]}}` for iTick) — a breaking change to the contract
  between `fetch_raw.py` and `merge.py`.
- `merge.py` now emits one row per historical bar per symbol (not one row per live quote);
  `change`/`change_pct` computed bar-over-bar per symbol, first bar per series is NaN.
- `analyze.latest_per_symbol(df)` added — collapses multi-row-per-symbol history down to most
  recent bar, needed before feeding `top_gainers`/`top_by_volume`/`top_volatility`/`region_growth`
  for "current standing" style views.

**Lesson for next cross-cutting contract change**: when 3+ agents must agree on a data shape,
have one agent define it explicitly and hand the identical spec text to every consumer, rather
than letting each infer it independently — avoids drift. For one unavoidable cross-dependency
between parallel agents, a getattr-guarded fallback let both proceed without a blocking
round-trip.

Known follow-up after any such contract change: existing on-disk data files (`data/raw/*.json`,
`market_data.db`) will be in the OLD shape and must be regenerated by a real (user-confirmed)
fetch — `tester` can verify code correctness against fixtures without doing this, but the
orchestrator must flag it rather than silently leaving the app broken against stale files.
